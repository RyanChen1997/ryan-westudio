# 操作流程

## 1. 先冻结原文，再交给 AI 整理

首次安装 `npm ci && npm run build`。除非用户明确指定其他位置，否则新项目用以下命令在系统临时根目录创建独立子目录；同一命令可在 Windows 的 PowerShell / CMD 和 macOS / Linux 的 shell 中运行：

```sh
node -e "const fs=require('node:fs'),os=require('node:os'),path=require('node:path'); console.log(fs.mkdtempSync(path.join(os.tmpdir(),'ryan-westudio-')))"
```

`os.tmpdir()` 以当前系统配置为准：Windows 通常使用 `TEMP` 或 `TMP`，macOS 通常使用系统设置的 `TMPDIR`，Linux 未配置临时目录时通常使用 `/tmp`。不手写这些路径或环境变量展开。将命令输出的路径作为下文的 `<项目目录>`，后续阶段复用；不要每一步都新建目录。引用路径时加引号，兼容带空格和中文的路径。

```sh
npm start -- --project "<项目目录>" --md "<原文绝对路径.md>" --prepare-only
# Word：--docx "<原文绝对路径.docx>"
```

程序保存只读 source.md、原文哈希清单、原始文件与必要的图片路径，不打开编辑器。Word 解析警告要处理，不能当作图片 OCR 或所有对象完整提取的证明。

AI 完整读取 source.md，另写 structured.md，只改明确的层级和格式，不擅自增删、改写或重排原文。正文有标题时先按实际结构定层级，最高一层从 H1 开始，不为模板效果改层级。原文开头的完整总标题移到 frontmatter 时仍计入原文对照，但不再充当正文 H1。实质歧义集中确认，明确结构不强制确认。发布拟题与简介不是必填项。

## 2. 结构化后自动对照并打开

如果用户指定[内置模板](style-presets.md)，用 `--preset` 明确套用；否则推荐并使用合适的现有模板，不另设选模板等待环节。

```sh
npm start -- --project "<项目目录>" --md "<项目目录>/structured.md" --source-md "<项目目录>/source.md" --open
# 指定模板：--preset blue-sequence
# 补图片搜索目录：--asset-dir /absolute/images
# 端口冲突：--port 4319
```

执行命令前，AI 确认 `structured.md` 的正文标题从 H1 开始、并列标题同级、子标题不跳级；没有自然标题时不硬加。总标题只在 frontmatter、正文有六个并列主章时，六章都用 `#`。详见[标题怎么处理](content-integrity.md#标题怎么处理)。

程序检查原文基准哈希、结构稿文字、原标题是否保留与正文顺序，不判断正文标题层级是否合理。失败提供差异，AI 修复 structured.md 后重跑，不改 source.md、不让用户关掉校验。

通过后才创建初始编辑状态并启动服务。所用模板可在同页切换；不增加画廊等待或人工校验按钮。直接导入未经过 AI 的 Markdown/Word 也可以，但没有独立原文基准时不声称已完成 AI 前后对照。

## 3. 所见即所得编辑与协作

用户直接编辑当前正文。AI 从同一个活跃页读 snapshot，以 revision + nodeId 提交操作，见 ai-tools.md。默认美化不改字；用户授权后才改内容。

换用内置模板时在同一编辑页操作，不重新导入或启动第二个编辑器。可在 GUI 手动加图和换图；用户要求 AI 添加或替换本地图片时，按 [AI 图片接口](ai-tools.md#ai-导入图片)在同一活跃页操作。

用户在编辑器里的改字、标题、图片和样式均为合法编辑，不再次对照初始原文，不做后台校验。正文视图与复制输出共用设计规则，没有“查看发布预览”开关。电脑/手机与夜间只是显示方式，不改存档。

块左侧悬停菜单按删除、上方插入、下方插入排列；图片多一项「调整图片大小」，10%–100% 十档等比缩放，编辑和复制输出共用同一大小。插入立即创建空段落，样式选择转换同一块，关闭选择器或取消图片保留空段落；若已被用户/AI 填写则不覆盖。「其他样式」暂不实现。文章右侧目录从真实 heading 更新，悬停/点击/键盘展开、章节跳转不改文档。

自动保存显示明确状态；失败不要刷新。刷新恢复文章、视觉和 revision，不恢复撤销栈和光标。一批操作一次事务，失败整批不提交；并发过期 409，读取最新状态再决定如何修改。

## 4. 简短交付与直接复制

排版完成后默认只用两句：说明实际用了哪个模板，再说能继续做的相关事项（如微调版式、添加本地图片、导出 HTML）。可插图和换图，但没有 Pro 的专门配图流程，也不能推送草稿箱。除非用户询问或需要处理问题，不主动展开过程、路径和文件清单。

点击「复制到公众号」，取当前 Tiptap 状态生成正文，不使用预先准备的旧 HTML，不重跑文字对照。图片编码、磁盘保存或并发冲突失败时明确提示，不假装成功。

用户到公众号编辑器粘贴、检查实际样式与图片，补标题和封面，自行发布。没有自动发布接口。微信可能进一步过滤内容，浏览器所见即所得不代表已完成微信真机验收。

## 5. 关闭与恢复

确认「已保存」再停止终端服务。恢复只用 `npm start -- --project <同一目录> --open`，不重新整理或对照最初原文。服务重启使用新认证 URL；一个目录只允许一个服务、一个活跃页。

用户询问或需要手动恢复时给出项目的实际路径。不要在流程结束后立即删除该目录，用户还可能继续编辑。系统可能清理临时目录；若需长期保留成品，请导出到用户指定的位置；若需保留可编辑状态，确认已保存、停止服务后再按用户要求归档整个项目（含 `project.json` 和 `assets/`）。
